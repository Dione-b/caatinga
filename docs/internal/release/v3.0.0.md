# v3.0.0

Breaking-change major release aligning Caatinga with `@stellar/stellar-sdk` v16 and Node 22.

## Breaking changes

- **Node floor raised to 22** (`engines.node >=22`, `.nvmrc` 22). SDK v16 requires `>=22.0.0`.
- **`ctg generate` now uses `npx --yes @stellar/stellar-sdk generate`** instead of the Rust
  `stellar contract bindings typescript` subprocess. Binding generation no longer requires the
  Stellar CLI to be installed. Custom networks pass `--rpc-url` only (passphrase is not needed to
  generate bindings); well-known networks pass `--network` + `--rpc-url`.
- **Generated bindings import path** is now the package root
  (`./<bindingsOutput>/<contract>`), matching the self-contained package emitted by the JS
  generator. Update imports from `…/src/index.js` to `…/<contract>`.
- **Templates** (`react-vite-counter`, `zk-starter`) bumped to `@stellar/stellar-sdk ^16.0.1`
  (Protocol 27, ESM-first, `@stellar/stellar-base` folded into the SDK).

## Added

- `CAATINGA_MULTI_AUTH_REQUIRED` — surfaced when an invoke needs non-invoker signatures
  (delegated Soroban address credentials / "AddressV2"); `AssembledTransaction.sign` raises
  `NeedsMoreSignaturesError`.

## Compatibility

- `@caatinga/client` `signAndSend({ signTransaction })` call is unchanged; v16 returns a
  `SentTransaction<T>` whose `sendTransactionResponse.hash` and `result` are normalized by the
  existing submit result handler. Full `signAuthEntry` multi-auth orchestration is **not supported until v1.0** in the browser adapter — application code only (`CAATINGA_MULTI_AUTH_REQUIRED`).
- Build/deploy/invoke still shell out to the Rust Stellar CLI under the existing version contract.
