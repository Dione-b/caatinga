# Caatinga v2.0.0-alpha.0

## Status

Alpha major release. Breaking changes on the Stellar CLI compatibility surface and removed override APIs.

## Packages

- `@caatinga/cli@2.0.0`
- `@caatinga/core@2.0.0`
- `@caatinga/client@2.0.0`

Install channel:

```bash
npm install -g @caatinga/cli@next
```

## Compatibility

- Node.js 20+
- Stellar CLI **minimum** `23.0.0` (hard failure below)
- Stellar CLI **last tested** `25.2.0` (advisory above; no override flag required)
- Rust 1.84+ with `wasm32v1-none` target

## Breaking changes

- Removed `STELLAR_CLI_TESTED_MAX_VERSION`; use advisory `STELLAR_CLI_LAST_TESTED_VERSION`.
- Removed `assertSupportedStellarCliVersion`; use `evaluateStellarCliCompatibility`.
- Removed `CAATINGA_UNTESTED_CLI_VERSION` error code.
- Removed `--allow-untested-stellar-cli` from `build`, `deploy`, `generate`, `invoke`, and `doctor`.
- Removed `allowUntestedStellarCli` from core command options.

## Added

- `evaluateStellarCliCompatibility()` returning `CompatibilityReport` with `warnings[]`.
- `checkStellarCliVersion()` export from `@caatinga/core`.
- `Diagnostic.warnings` on `caatinga doctor` (e.g. `STELLAR_CLI_UNTESTED_VERSION`).

## Migration

Remove `--allow-untested-stellar-cli` if you used it locally — newer Stellar CLI versions now run with a non-fatal advisory. For CI gating on CLI version, rely on `CAATINGA_UNSUPPORTED_CLI_VERSION` (hard floor only).

## Highlights

- Feature-aware Stellar CLI compatibility (hard floor + advisory last-tested)
- Template init no longer copies local `target/` build artifacts
- Competitive landscape docs: Scaffold Stellar positioning in `docs/architecture.md`

## Known limitations

- Alpha stability; APIs and artifact formats may still change before v1.
- No automated npm/GitHub release pipeline yet — publish remains operator-controlled.
