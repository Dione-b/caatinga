# Lint + Prettier Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add root-level ESLint and Prettier configuration to the Caatinga monorepo with Turbo integration.

**Architecture:** Single shared config at the repository root using ESLint flat config (`eslint.config.js`) and Prettier (`.prettierrc`), ignoring generated artifacts and lockfiles, exposed through root `package.json` scripts and `turbo.json` tasks.

**Tech Stack:** ESLint 9, @eslint/js, typescript-eslint 8, eslint-config-prettier, Prettier 3, pnpm, Turbo.

## Task 6: Run lint and fix issues

**Files:**

- Potentially modify: any `*.ts`, `*.tsx`, `*.js`, `*.mjs` files with auto-fixable issues

- [ ] **Step 6.1: Run lint to see current violations**

Run: `pnpm lint`
Expected: list of lint errors/warnings

- [ ] **Step 6.2: Apply auto-fixes**

Run: `pnpm lint:fix`
Expected: auto-fixable issues resolved; remaining issues printed if any

- [ ] **Step 6.3: Manually fix remaining non-auto-fixable issues**

For each remaining error, edit the source file to resolve it. Common examples:

- Remove unused variables.
- Replace `any` with proper types.
- Fix `no-undef` by adding imports or globals.

If a rule is too noisy for the codebase, add a targeted override in `eslint.config.js` rather than disabling case-by-case. Example:

```javascript
{
  files: ["scripts/**/*.mjs"],
  rules: {
    "no-console": "off"
  }
}
```

- [ ] **Step 6.4: Verify lint passes**

Run: `pnpm lint`
Expected: exit code 0, no errors
